Project plan: three Agile sprints

The project was developed in three one-week sprints. Each sprint followed the Agile phases of planning, analysis, design, implementation, testing and maintenance. The table below records what was planned, what was delivered and what problems appeared in each sprint.

Sprint Phase / tasks Delivered in this sprint Sprint review
Sprint 1
Week 1		 Planning and analysis: read the assignment brief, list every required page and function, sketch the file structure, collect three study images. Folder structure, four empty HTML pages, shared navigation bar, base stylesheet. Structure was clear, but the four pages had no shared style at first and looked inconsistent. Fixed by moving all colours and spacing into style.css.
Sprint 2
Week 2		 Design and implementation: build the home page carousel, the login form and the task form with all required fields. Working carousel, login that blocks wrong credentials, task form with title, course code, course name, due date, description and notes. Two bugs were found in this sprint: HTML written inside a task title broke the table, and the date calculation produced a decimal number of days. Both are documented below.
Sprint 3
Week 3		 Implementation and testing: add edit and delete, store data in localStorage, add validation messages and the live clock, then test every page in Chrome. Full CRUD, validation for required fields and dates, delete confirmation, live clock, README document and final screenshots. All assignment requirements were checked against the marking sheet; the remaining work is to commit the project to GitHub in several steps.

Troubleshooting log

Two problems that appeared while building the task manager, with the failing code, the investigation, and the corrected code.

Bug 1 · A task title containing HTML tags broke the whole table

Found: 8 November 2026, 21:40  |  Fixed: 8 November 2026, 22:25

While testing the add-task function I typed the title <b>Coursework</b> blog page to see whether special characters were handled. The row was created, but the bold tag was executed as real HTML: the title appeared in bold, wrapped onto two lines and no longer matched the typography of the other rows. A script tag typed into the same field would have run as well.

Error screenshot

Code that caused the problem (the value was inserted into the row with innerHTML, so the browser parsed it as markup):

row.innerHTML =
  "<td><strong>" + task.title + "</strong>" +
  daysLeft(task.due) + "</td>";

Investigation: I compared the row with a normal task and saw that only the row with angle brackets was broken, so the problem was in the way the string was inserted, not in the data itself. I checked the MDN page on innerHTML and on the Element.textContent property, which confirmed that innerHTML parses markup while text should be escaped.

Corrected code: every user value now goes through an escaping function before it is placed into the row:

function escapeHtml(text) {
  if (!text) return "";
  return text
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;");
}

row.innerHTML =
  "<td><strong>" + escapeHtml(task.title) +
  "</strong>" + daysLeft(task.due) + "</td>";

Result after the fix: the same title is now displayed as plain text, the table keeps its width and no markup is executed.

Bug 2 · The "days left" label showed a decimal number

Found: 9 November 2026, 10:15  |  Fixed: 9 November 2026, 10:50

The label under a task title should say how many days remain before the deadline. In testing it showed 0.3852147337962963 days left, which is unreadable and looks like broken output on a page that is otherwise finished.

Error screenshot

Code that caused the problem (two dates were subtracted without rounding, and the current time of day was included in the result):

const diff = (new Date(task.due) - new Date()) / 86400000;
return "<span class='tag'>" + diff + " days left</span>";

Investigation: subtracting two dates returns milliseconds, and because new Date() contains the current hour and minute, the division never gives a whole number. I read the MDN pages on Date and Math.round and decided to remove the time part from both dates before subtracting.

Corrected code:

function daysLeft(due) {
  const today = new Date();
  today.setHours(0, 0, 0, 0);
  const target = new Date(due);
  const diff = Math.round((target - today) / 86400000);

  if (diff === 0) return "<span class='tag'>Due today</span>";
  if (diff === 1) return "<span class='tag'>1 day left</span>";
  return "<span class='tag'>" + diff + " days left</span>";
}

Result after the fix: the label now reads 1 day left, and the same date always produces the same number regardless of the time of day the page is opened.
